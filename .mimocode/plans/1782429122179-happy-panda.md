# Plan: 对齐 Python akshare 全部功能到 Rust

## 现状分析

### Rust 侧 (akshare-rs)
- **18 个模块**, **1,535 个 pub async fn**
- 主要数据源: Eastmoney (push2/datacenter), Sina, Tencent, Jin10, THS, CNINFO, 交易所 API, Yahoo, Stooq, Xueqiu
- Feature gate 系统: `mod-xxx` 细粒度 + category 聚合
- 测试: mock (wiremock) + E2E (RUN_E2E=1)

### Python akshare 侧
- **25 个类别**, **~1,100 个 API 端点**
- 股票 ~383, 期货 ~68, 债券 ~45, 期权 ~53, 基金 ~89, 指数 ~87, 宏观 ~215, 外汇 ~11, 现货 ~13

### 差距
Rust 侧在 stock (469) 和 macro_data (423) 上已超 Python，但在以下领域有缺口：

| 类别 | Python | Rust | 差距 | 优先级 |
|------|--------|------|------|--------|
| 股票-基本面/财务 | ~80 | ~30 | -50 | P1 |
| 股票-龙虎榜/资金流 | ~25 | ~15 | -10 | P1 |
| 股票-概念/行业板块 | ~20 | ~10 | -10 | P1 |
| 股票-融资融券 | ~8 | 0 | -8 | P2 |
| 股票-大宗交易 | ~6 | 0 | -6 | P2 |
| 期货-库存/仓单 | ~15 | ~8 | -7 | P2 |

| 已损坏的 API | - | 12 | - | P0 |

## Rust 风格和最佳实践

### 1. 函数签名
```rust
// 标准模式
pub async fn function_name(&self, param: &str, limit: usize) -> Result<Vec<DomainType>> {
    // 参数验证
    if param.is_empty() {
        return Err(Error::invalid_input("param is empty"));
    }
    // 调用 provider
    self.provider_method(param, limit).await
}
```

### 2. 错误处理
- 使用 `?` 传播错误
- 上游 API 失败用 `Error::upstream()`
- 数据为空用 `Error::not_found()`
- 参数错误用 `Error::invalid_input()`
- 解析失败用 `Error::decode()`

### 3. 数据源抽象
- 新函数优先使用已有的 provider 方法 (`dc_fetch_all`, `kline_fetch`, `clist_spot_fetch`)
- 如果现有 provider 不支持，新增 provider 方法
- 多数据源时实现 fallback chain

### 4. Feature gate
- 新模块使用 `mod-xxx` feature gate
- 在 `lib.rs` 中添加 `#[cfg(feature = "mod-xxx")]`
- 在 `Cargo.toml` 中添加到对应的 category aggregator

### 5. 测试
- 每个新函数必须有 mock test
- Mock test 使用 wiremock，验证 API 调用不 panic
- E2E test 标记 `#[ignore]`，需要 `RUN_E2E=1`

### 6. 类型定义
- 新 domain type 放在 `types/mod.rs`
- 使用 `#[derive(Debug, Clone, Serialize, Deserialize)]`
- 字段使用 `pub` 可见性
- Option 包裹可能为空的字段
